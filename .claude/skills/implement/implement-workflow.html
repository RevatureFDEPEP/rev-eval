Before running · Prerequisites

What must already be true for /implement to have a source of truth

① Feature is documented
The detail doc docs/features/w#-f#-<name>.md exists with Steps / Depends on / Unblocks / Notes, a row in docs/FEATURE_STATUS.md, and the upstream section in days_*_features.md. These are the acceptance checklist — no doc, nothing to plan from.
② Prerequisite features are done (or the gap is known)
Everything in the feature's Depends on is ✅ in FEATURE_STATUS. If not, the skill surfaces the gap rather than planning on an unmet prerequisite.
③ Knowledge Graph ready for related-feature lookup
Layer 1 (kg.py structure W#-F#) is offline/deterministic — always available, no setup. For semantic "how was a similar feature built" lookups, Layer 2 needs kg.py up then a prior kg.py ingest, then kg.py query "…" — needs Docker + ~5GB Ollama models.
④ Repo state clean & on richardh
cwd is the rev-eval/ repo root (has docker-compose.yml + docs/features/); local richardh fetched/pulled, working tree clean, origin reachable.
⬇ run /implement W#-F# ⬇

After running · Outcomes & follow-ups

End state when the gates pass — and the manual steps the skill leaves to you

✓ Feature branch pushed (gates passed)
richardh-feat-W#F# on origin — but only if tests were green and every Step was confirmed. If a gate failed, the branch stays local and the skill reports exactly what's outstanding (no push).
✓ Docs updated in-branch
Plan committed in docs/plans/; detail-doc Steps checked off with evidence (file:line / commit); the FEATURE_STATUS.md row flipped to ✅ — all on the feature branch.
✓ Knowledge Graph re-ingested (best-effort)
New plan / detail doc / ADR / status row folded into the KG so future planning sees them. Layer 1 is live automatically; Layer 2 needs kg.py up → ingest → down. Deferred (not failed) if Docker/models unavailable.
↪ Manual follow-up (outside the skill)
Open PR richardh-feat-W#F# → richardh, review, merge. File any adjacent defects spotted during the work as separate features — the skill never expands scope.

Conventions: branches always base off richardh (never main); branch name has no dash between W&F (richardh-feat-W2F4); plans are version-controlled; scope never exceeds the feature spec (adjacent defects → separate feature); KG is a local dev tool, never in compose/ROUTES.
