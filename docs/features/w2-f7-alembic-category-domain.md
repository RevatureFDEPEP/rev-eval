# W2-F7 — Relational Schema Evolution: Alembic Migrations & Category Domain

**Status:** ✅ Completed
**Spec:** `days_6_10_features.md` §7 (Day 10)
**Unblocks:** W3-F1 (Quiz Session Creation Backend — sessions table is a new Alembic migration on this schema), W4-F1 (Candidate Results Reporting Endpoints — reporting Alembic env builds on this pattern)
**Last updated:** 2026-06-05 (branch `richardh-feat-alembic`)

Extend test-management-service's relational models with a "Question Categories"
domain and bring schema changes under Alembic migration control.

## Steps

- [x] **1. Category model** — `Category` (`categories`) with M2M to `Skill`
      via a plain `category_skills` association `Table` (unique on
      category_id+skill_id). `Skill.categories` is a viewonly reverse.
      Evidence: `services/test-management-service/src/models/category.py`,
      `src/models/skill.py`.
- [x] **2. Initialize Alembic** — `alembic init -t async` inside
      `services/test-management-service/`. `env.py` imports all models onto
      `Base.metadata`, resolves the URL at runtime (`DATABASE_URL` or
      `settings.SQLALCHEMY_DATABASE_URL`, forced to asyncpg) and filters
      autogenerate with `include_object` so tables owned by user-service in
      the shared DB (`users`) are ignored. Evidence: `alembic.ini`,
      `alembic/env.py`.
- [x] **3. Autogenerate migration** — chain of three revisions (see Notes):
      `0001` baseline of the pre-Alembic schema, `0002` "Add categories and
      skills relationship" (autogenerated, reviewed), `0003` demo-data seed.
      Verified on scratch Postgres 16: `upgrade base→head`, downgrade
      round-trip, `alembic check` reports no drift. Evidence:
      `alembic/versions/0001..0003*.py`.
- [x] **4. Domain layers** — standard vertical slice: `category_schema.py`,
      `category_repository.py` (skills eager-loaded via `selectinload`),
      `category_service.py`, `v1/routes/category_route.py` (CRUD +
      `POST/DELETE /categories/{id}/skills/{skill_id}/`, `GET
      /categories/{id}/skills/`; link/unlink idempotent). Unit tests:
      `tests/test_category_service.py`, `tests/test_category_schema.py`.
- [x] **5. Gateway routes** — `^/v1/api/categories(/.*)?$` →
      test-management-service in `services/api-gateway-service/main.py`.

## Notes

- **Decision — `create_all` removed entirely** (was: "keep for dev or defer
  to migrations"). `init_db()` now only registers models and checks
  connectivity; `start.sh` applies `alembic upgrade head` and fails hard so
  compose restarts on migration errors. Alembic owns structure **and**
  seeding.
- **Migration chain:** `0001` baseline (existing 4 tables) → `0002`
  categories → `0003` demo seed (replaces `seed_db.py`; idempotent per
  table). Legacy volumes that predate Alembic are detected in `start.sh`
  (`skills` exists, `alembic_version` doesn't) and stamped at `0001` so only
  newer revisions apply.
- **Users seeding moved to user-service** (it owns the `users` table in the
  shared DB): `services/user-service/src/db/seed.py`, called on startup
  before `/health` responds — compose ordering guarantees the trainer ids
  that `0003` needs. If users are missing, `0003` raises and is *not*
  recorded, so the container retry self-heals.
- The reporting service ([W2-M10](w2-m10-reporting-service-scaffold.md)) reuses the
  Alembic pattern established here.
