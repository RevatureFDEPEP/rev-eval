# W5-F12 — Schema migration coverage (user-service Alembic + question-doc shape)

**Status:** ❌ Not Started
**Spec:** trainer-defined remediation (non-catalog). Origin:
[technical-debt.md](../technical-debt.md) §4; **repayment backlog item 3**.
**Depends on:** user-service, question-management-service. Pairs with
[W5-F6](w5-f6-user-service-repository-layer.md) (which deferred Alembic) and
[W5-F3](w5-f3-legacy-true-false-rendering.md) (legacy doc shape).
**Unblocks:** versioned, reproducible schema for the two services lacking it.
**Last updated:** 2026-06-17

## Problem

- **user-service uses `Base.metadata.create_all`** (med) — no version history /
  rollback; cross-env drift is invisible and unreproducible. Only
  test-management-service is Alembic-owned.
  `services/user-service/src/db/session.py`.
- **question-management-service: implicit Beanie/ODM schema** (med) — Mongo is
  schemaless, but field-shape changes (W2-F6 vs. legacy question docs — see W5-F3)
  have no recorded migration story.
  `services/question-management-service/src/db/session.py`.

(The reporting-service empty Alembic `0001` is an intentional recorded decision per
ADR 0001 — *not* debt; excluded here.)

## Steps

- [ ] **1. Bring user-service under Alembic** — add an `alembic/` chain mirroring
      test-management-service's setup (env, `start.sh` `alembic upgrade head`),
      baseline the current user schema as the first revision, switch `init_db()` to
      connectivity-check only (stop `create_all`). Wire into compose startup + the
      local-run docs.
- [ ] **2. Question-doc shape migration story** — define and document how Mongo
      question-doc shape changes are versioned/applied (a versioned, idempotent
      migration script + a `schema_version` field convention, or equivalent). Cover
      the legacy `true_false` shape (coordinate with W5-F3's normalization path if
      that route is chosen).
- [ ] **3. Verify** — fresh `docker compose up` applies user-service migrations;
      an autogenerated revision after a trivial model change is clean/empty
      (baseline accuracy check).
- [ ] **4. Docs** — update CLAUDE.md so user-service model changes route through
      `alembic revision --autogenerate`, like test-management-service.

## Out of scope

- A general Mongo migration *framework* — a documented, repeatable shape-change
  story is sufficient at this scale.

## Acceptance

- [ ] user-service schema is Alembic-owned (no `create_all`); fresh stack migrates.
- [ ] Question-doc shape changes have a documented, repeatable migration path.
- [ ] Tests/startup green; `FEATURE_STATUS.md` row ✅; debt §4 / repayment 3 cross-referenced.
